# Figma 原型设计说明 · AdInsight Agent 0.3

本文件是可复现当前 React 工作台的原型说明，不是已上传到 Figma 的在线设计稿。业务资料与指标全部为 mock。

## 1. 设计风格
B 端 AI 工作台，信息优先、紧凑、克制。用分隔线、标签页和排版区分区域，不使用套卡片、渐变装饰、浮动大面板或营销式 Hero。绿色只承担主操作和完成状态；正文用中性灰，指标辅以蓝色，风险用琥珀色。

## 2. 画布与尺寸
Desktop：1440 × 1024。另建 1280 × 720 和 Mobile：390 × 844 检查重排。
Desktop 顶栏 77 高，任务工具栏约 60 高；工作区填满剩余高度。左栏 306 宽、右栏 Fill。左栏表单内部滚动，底部主按钮固定；右栏独立滚动，标签栏吸顶。
780px 及以下改成整页单列，表单在前、结果在后；标签栏横向滚动，不挤压文字。禁用桌面左右独立滚动规则。

## 3. 页面结构
1. 顶栏：品牌图标、AdInsight Agent、定位、小型版本标记；右侧是模型配置状态、个人项目 / 合成数据标签。
2. 任务工具栏：Campaign 研究 / 广告创意交付双入口；研究模式保留历史选择、删除按钮、新建任务。
3. 输入侧栏：编号 01、标题、清空；示例选择、基础表单、折叠约束与数据场景；固定主按钮。
4. 右侧：编号 02、任务标题与状态；六阶段状态栏；五个结果标签页。
5. 底部：数据免责声明。执行记录和来源作为结果标签页，不再同时铺在长页面底部。

## 5. 各区域布局
### 输入
全宽字段纵向排列，投放平台 / 预算并排。产品类型使用下拉框，地区为输入框，目标用户 / 目标 / 当前问题为多行文本。选填说明和 mock 数据场景放在 disclosure 内。创建任务后输入快照锁定；底部动作改为“基于此 Brief 新建任务”。

### 研究结论
页首显示产品 / 地区 / 命中来源数。两列“用户与市场”“竞品与机会”，条目使用细编号、标题、正文、来源 ID。风险用折叠区。页面下部为浅色人工确认区域，包含三种方向、修改意见、声明复选框和确认按钮。不是聊天气泡。

### Campaign Brief
顶部文档状态和复制 / 下载图标；产品名、地区 / 类型、副信息条。正文分 10 节：背景、目标、用户、洞察、卖点、方向、渠道、A/B、指标、证据与限制。底部规则检查及待核验事项。

### 复盘与实验
五项指标横条；下方两列转化路径图和待验证问题。路径图展示原始计数，条长按曝光基数比例绘制，极小值最小可见宽度要注明。再下方为样本量 / 周期 / MDE、A/B 两版本、统计假设。沙盘默认折叠。

### 执行与工具
两条 MCP 连接行，每条展开显示工具名和描述。其后是 Agent 分工列表、工具调用列表、时间事件。技术输入输出只在用户展开时显示，等宽字体，JSON 区可滚动。

### 知识来源
四类知识数量条与本次命中来源列表。点击来源或正文 source ID 打开同一详情弹窗。相似度旁明确“不是事实置信度”。

## 6. 交互状态
- 示例选择：立即替换可编辑表单；任务开始后不可直接覆盖该输入。
- 开始研究：主操作禁用，六个阶段显示真实状态。市场 / 竞品 / 复盘同时进入 running。
- Loading：阶段旋转图标；未返回的研究用简单脉冲占位。不能模拟 token、假百分比或随机完成步骤。
- 待确认：生成停止，三个方向可选；声明未勾选不可提交；保留修改意见。
- 生成完成：Brief 可复制 / 下载，阶段全部 completed，但质检仍有人工核验提示。
- 复制：图标暂时切换勾选，并使用“已复制”可访问名称。失败提示可改用下载。
- 模型降级：顶部显示受影响 Agent，执行行显示“降级 Mock”与原因。
- 来源弹窗：遮罩、摘要、原始 JSON；关闭回到原触发元素。
- 历史恢复：选择任务，展示输入快照及阶段状态。
- 取消 / 失败：保留已有研究；不自动生成最终 Brief。
- Reduced motion：禁用进入、旋转、进度过渡。

## 7. 页面文案
模块标题：Campaign 输入 / 研究与决策 / 用户与市场 / 竞品与机会 / 确认这一轮要验证的创意方向 / 交付前检查 / 待验证问题 / MCP 连接。
空状态：尚未开始 / Brief 尚未生成 / 暂无匹配来源。
Loading：并行研究中 / 生成 Brief 中 / 实时连接重连中，已保留当前结果。
按钮：开始研究 / 确认并生成 Brief / 基于此 Brief 新建任务 / 恢复任务数据。
重要提示：个人独立 Demo；全部业务数据为 mock；目标为演示假设，不是行业基准；讨论稿，未执行投放。
不使用“成功提升转化”等未经验证的结果文案。

## 8. Figma 制作步骤
1. 建 Page：Foundations、Components、Workspace、States。使用中文字体 PingFang SC / Noto Sans CJK 与通用无衬线字体。
2. Foundations 定义颜色、字号、行高、4/8/12/16/24/32 间距变量，字距全部 0。
3. 制作 Input、Select、Textarea、Icon Button、Button、Tag、Metric Cell、Step、Source Row、Disclosure 等组件；各自具有 default / hover / focus / disabled / error variant。
4. 按 Desktop 尺寸创建 Frame，使用纵向 Auto Layout 组织顶栏、工具栏和剩余工作区。
5. 工作区使用横向 Auto Layout；左栏固定宽度，右栏 Fill。左侧按钮固定到表单区底部。
6. 为右侧建立五个 Tab variant，正文分区域，避免把容器再套成卡片。
7. 建立 Empty、Researching、Approval、Generating、Completed、Fallback、Failed、No Evidence、No Sample 状态 Frame。
8. 在 Prototype 中连接开始研究、阶段完成、方向确认、复制反馈、来源 Overlay 和历史切换。协议操作标为演示交互，不伪装为 Figma 内部真实联网。
9. 动效使用 160–300ms Ease Out；状态栏与内容变更可用 Smart Animate，不让文字位置跳动。
10. 从主 Frame 派生 1280、390 宽版本，测试长产品名、长地区、多条引用、零数据、错误文案；检查输入、正文和按钮没有横向溢出。

## 9. Figma AI / FigJam / Figma Make Prompt
> 创建 AdInsight Agent 0.3 研究模块的中文 B 端 AI Campaign 工作台原型，桌面 1440×1024，兼容 390×844。顶部品牌与模式，任务工具栏带历史选择。左侧 306px Brief 表单，底部固定“开始研究”；右侧六阶段状态与五个标签页：研究结论、Campaign Brief、复盘与实验、执行与工具、知识来源。不要做营销落地页或聊天机器人，不要卡片嵌套，不要渐变装饰。采用白色、中性灰、深绿主操作，蓝色指标、琥珀风险，1px 分隔线，最大圆角8，Lucide 图标。研究展示用户动机、市场偏好、本地化方向、竞品卖点、差异化假设及可点击 source ID。市场、竞品、复盘三分支并行；研究结束后暂停，等待人工选择三个创意方向之一、填写意见并勾选合成数据声明，才生成 Brief。复盘展示由曝光128000、点击2432、转化151、花费1932.8、收入2609.28计算的指标，A/B计划每组约6477点击、44天、相对MDE20%，全部标记为演示数据而非真实效果。执行区展示3个只读MCP服务、7种工具及输入输出记录。为无来源、无样本、失败和模型降级制作状态。轻量进入动画和真实状态转场，不伪造随机执行进度。所有页面注明：个人独立项目、合成资料、讨论稿、未执行投放。

## 0.3 广告交付原型
在同一文件新增 Creative Delivery Frame Set，不创建营销首页。保留既有白底、绿色主操作、中性灰线、琥珀提醒；图片素材提供实际视觉焦点，不使用装饰背景。

桌面 1440 × 1024：顶栏与模块导航共 137 高；左需求栏 292 宽，表单内滚动，主按钮固定；右内容 Fill，padding 30。小于 1100 的编辑与交付双栏改为单列，780 以下整页顺序排列。所有区域为分隔线布局，仅历史素材重复项用 6px 圆角卡片。

按以下状态画 6 个 Frame：
1. Creative / Library：左侧需求；右侧四步进度、两种路径选择、搜索、2–3 列 4:5 素材缩略图；选中边框与勾选；底部来源摘要。
2. Creative / Prompt：同样需求侧栏，右侧用四行展示产品、人群、目标与交付条件，不填充虚构历史证据。
3. Creative / Plan：左侧需求锁定；右侧正文编辑区和模型选择区。标题 / 正文 / CTA / 画面 / 提示词 / 禁用内容；分镜折叠；参考图片 86 × 108。模型用 radio rows，显示已配置或缺失密钥。
4. Creative / Generating：固定画幅预览区、真实任务状态与轻微扫描线；不使用虚假完成百分比。结束后 PNG 替换等待区。
5. Creative / Delivery：图片完整可见、交付清单、来源、PNG / ZIP 下载；内容快照折叠；人工验收 checkbox 和确认按钮。
6. Creative / Review：绑定 V1 和短 ID；模拟原始计数表单；提交后五项指标、异常说明、未执行实验假设；改版意见与“带入复盘，创建 V2”。

Prototype 连接：
Brief“制作广告”→ Library（已关联 Brief）；独立入口→ Library（独立需求）；路径切换→ Prompt；选素材+提交→ Plan；确认→ Generating→ Delivery；验收→ Review；创建 V2→ Plan（带复盘条与父版本入口）。这是一条循环，不以复制文本结束。

状态文案：无匹配“没有匹配的历史素材”；规划“检索与规划中”；图像“等待模型返回图片”；失败“本次未完成交付”；本地结果“本地排版预览 · 非图像模型生成”；配置缺失“未配置密钥”。外部生成增加发送数据与可能费用确认，缺失密钥时生成按钮不可用。

动画：200–250ms 内容淡入与小幅上移；选中素材边框 160ms；真实等待旋转图标；尊重 reduced-motion。不要让动画改变卡片尺寸、挤压文字或遮挡主操作。

### Figma Make / AI Prompt
请根据 AdInsight Agent 0.3 构建桌面 1440×1024 的出海营销 SaaS 工作台。顶部两个模块“Campaign 研究”和“广告创意交付”。广告模块左侧 292px 客户需求栏，右侧四步：需求与素材、提示词与模型、广告交付、复盘与下一版。提供“复用历史素材”“从提示词创作”两条入口，用有完整图片的 4:5 缩略图选择参考。方案可编辑文案与视觉提示，模型单选包含本地排版、OpenAI GPT Image 2、Google Nano Banana 2，明确缺少密钥与费用确认。交付页显示完整广告图片、来源、PNG 与 ZIP 下载、人工验收。复盘页显示五项指标、异常、改版意见，创建 V2 后回到方案确认。白底、中性灰分隔线、绿色主按钮、5–6px 圆角，仅素材列表用卡片，不套卡片、不做 Hero、不使用装饰光球。真实运行状态动画不伪造进度。全部案例标为合成，视频仅分镜和提示词，不画自动投放按钮。
