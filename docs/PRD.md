## 1. 文档信息
| 项目 | 内容 |
|---|---|
| 产品名称 | AdInsight Agent｜出海营销用户洞察与 Campaign Brief 生成助手 |
| 版本 | 0.3，策略到广告交付闭环 |
| 作者 | Metre888，个人独立项目 |
| 更新日期 | 2026-09-07 |
| 项目性质 | 个人独立作品集 Demo，非公司正式项目 |
| 数据边界 | 全部业务资料、竞品与投放数据均为合成 mock |

## 2. 项目背景
出海营销团队在制定 Campaign 时需要综合产品信息、市场差异、目标用户、竞品表达和历史复盘。材料分散使 Brief 容易遗漏约束、泛化用户动机，也使创意判断难以追溯。本项目基于这一通用工作场景设计，不将个人观察表述为正式公司成果。

0.1 已验证从表单到文本结果的基本体验。0.2 将产品目标进一步收敛为：让营销人员在证据和指标支持下，完成一次可追溯的策略决策，而非直接得到未经确认的营销长文。

0.3 将已确认策略延伸到客户可验收的广告图片：素材或提示词 → 图像模型 → 交付版本 → 复盘 → 下一轮创意。原有研究流程保留，新增独立客户需求入口。

## 3. 用户痛点
- 资料分散：用户需要重复整理和对齐目标、市场、预算、素材问题。
- 泛化结论：语言流畅不意味着适用当前国家和产品，容易混入无关案例。
- 决策断层：分析与 Brief 之间缺少用户确认，创意方向选择缺少记录。
- 复盘口径混乱：百分比缺乏原始计数，不能定位公式或归因问题。
- 过程不可见：模型失败、检索不足、工具异常经常被包装成成功输出。
- 信息过载：所有结果同时铺开、层层卡片，影响判断与复用。

## 4. 目标用户
| 用户 | 核心任务 |
|---|---|
| 出海营销产品经理 | 对齐需求与约束，组织策略评审 |
| 广告优化师 | 理解转化漏斗，形成下一轮实验假设 |
| 运营 / AIGC 团队 | 将用户洞察转成素材方向和具体表达 |
| 中小广告主 | 形成第一版可讨论 Brief，识别信息缺口 |

## 5. 产品定位
面向出海营销团队的 AI Campaign 研究与决策工作台。输入结构化 Brief，检索本地资料，完成并行分析，经人工确认形成附带引用、指标口径和验证计划的讨论稿。

不定位为自动广告投放系统、真实竞品监测系统或效果保证服务。

## 6. 核心目标
- 可完成：无 API Key 时仍能走完整流程。
- 可解释：每个工具、Agent、来源与人工决策可以回看。
- 可控制：研究与生成之间设置人工确认，取消后不能继续生成。
- 可验证：数字来自确定性函数，市场推断明确标为假设。
- 可复用：结果、输入快照、来源和修改意见持久化，支持复制和 Markdown 导出。

## 7. 需求范围
P0：输入与校验、三类示例、中文 RAG、三种 MCP 服务、三分支并行研究、人工确认、Brief、复盘与实验估算、执行记录、模式降级、历史恢复、取消、导出。
P0 新增：历史素材 MCP、可编辑创意方案、模型白名单、图像生成授权、图片 / ZIP 下载、交付确认、版本复盘、父版本迭代。
P1：只读真实资料连接、离线检索评测、多语言审校。
不在本版：账号与租户、投放写操作、真实市场数据、在线实验、向量数据库、模型自主选择任意工具。

## 8. 用户使用流程
进入工作台 → 使用示例或填写 Brief → 开始研究 → 解析 → 并行市场 / 竞品 / 复盘 → 查看证据和指标 → 选择方向并确认 → 生成 Brief → 规则质检 → 制作广告 → 素材复用 / 提示词 → 人工确认内容与模型 → 生成图片 → 人工确认交付 → 模拟投放复盘 → 下一版创意方案。

异常分支：输入不合法留在表单；模型失败按阶段降级；MCP 失败保留阶段结果并标记失败；取消进入终态；重启后运行中任务标记中断，待确认任务可继续。

## 9. 功能结构
单页面工作台。顶部为品牌、运行模式与历史任务；左侧为 Campaign 输入与固定主操作；右侧为阶段进度及五个结果标签页：研究结论、Campaign Brief、复盘与实验、执行与工具、知识来源。来源明细使用对话框，风险和技术日志按需展开。

## 10. 功能详细说明

### 10.1 Brief 输入
必填：产品名称、产品类型、目标国家 / 地区、目标用户、营销目标。
选填：投放平台、预算范围、当前问题、补充说明。附加三种合成数据场景：转化流失、达到演示目标、尚无样本。
默认展示 LumaSnap AI，可选择 LinguaLoop 和 Pocket Quest 示例。产品名最长 100 字符、地区 200 字符、其他字段 2000 字符。去除首尾空白，空必填字段拒绝提交。
创建任务后锁定输入快照；修改需基于当前 Brief 新建任务，不覆盖旧版本。草稿存在浏览器 localStorage。

### 10.2 Brief 解析
规则型 Parser 提取产品、市场、受众、目标和约束，记录选填缺口。不将未提供的信息自动补成事实。不消耗 LLM token。输出保存为 parse。

### 10.3 市场洞察
Market Insight 通过 knowledge MCP 查询市场资料，按当前产品和地区匹配。输出目标用户动机、合成市场偏好、本地化表达方向及风险。每条证据使用稳定 source_ids；无来源时明确标明需要补充研究。
DeepSeek 模式下结构化生成；无 key 或输出校验失败时使用本地可重复模板。

### 10.4 竞品分析
Competitor Analysis 通过同一 MCP 接口检索竞品案例，分析候选卖点、内容风格、渠道策略及差异化假设。虚构竞品不能代表真实市场份额，同类卖点不能直接视为本产品已具备能力。

### 10.5 人工确认
研究和复盘完成后任务暂停。用户选择“真实过程与结果”“高意图场景”“本地场景验证”之一，可填写 1500 字符以内修改意见，必须确认合成数据声明。
确认时间、方向和原始修改意见写入任务。状态校验拒绝提前或重复确认。此操作只授权生成讨论稿，不授权投放。

### 10.6 Campaign Brief 生成
Campaign Agent 使用输入、市场 / 竞品研究、复盘、历史 Campaign 证据及人工意见生成背景、目标、受众、核心洞察、候选主张、创意方向、渠道与 A/B 建议、引用和限制。
核心指标单独由确定性定义提供，不允许 LLM 改写计算值。规则质检检查引用存在性、确认记录、指标来源及四类知识覆盖，并保留待核验事项。完成后提供复制与 Markdown 下载。
“质检通过项”不等于真实事实或平台政策已经审查完毕。始终以讨论稿交付。

### 10.7 RAG 来源展示
本地 13 条资料，市场 4、竞品 4、Campaign 3、复盘 2。每条包含 id、source_type、title、summary、relevance_reason、score、is_mock 和原始 content。
字符 2–4 gram TF-IDF 负责排序，产品类型与市场范围负责过滤。分数是文本相似度，不是事实置信度。知识集合未命中时不补入无关材料。引用弹窗说明摘要、相关性和合成边界。

### 10.8 投放复盘与实验
measurement MCP 读取原始合成计数并校验：转化 <= 点击 <= 曝光，采纳素材 <= 提交素材，计数和金额非负且有限。
CTR=点击/曝光；CVR=关键转化/点击；CPA=花费/关键转化；ROAS=归因收入/花费；素材采纳率=采纳素材/提交素材。分母为零返回 null，显示不可计算。
以本版演示口径为例，转化事件为试用完成；游戏等业务真实接入前需重新定义关键事件。演示目标 CTR 1.5%、CVR 8%、CPA $15、ROAS 1.5、素材采纳率 50%，均不是行业基准。
复盘区展示指标、比例条图、异常与假设、对应历史案例、下一轮单变量测试。独立沙盘改变的是临时展示，不更新当前任务。
实验为固定样本两比例估算：双侧 95% 置信水平、80% 功效、相对 MDE 20%、流量 50/50；按每日 300 次点击估算，至少覆盖 7 天。未达到样本不宣布赢家。本版不执行真实实验。

### 10.9 Agent 与 MCP 可观测性
6 个阶段展示输入、任务、输出、状态、耗时及实际运行模式；市场、竞品、复盘分支真实并行。
全系统三个 stdio MCP 服务共 7 个只读工具定义，研究使用 knowledge / measurement 的 5 个定义，广告服务增加 creative 的 2 个定义。支持 tools/list 与 tools/call；展示只读声明、输入 Schema、调用输入输出、错误和耗时。Agent 只能调用自身白名单工具，不向浏览器或模型暴露任意执行入口。
SSE 提供 revision 标记的完整快照；5 秒轮询作为代理缓冲或断线的兜底，不制造假进度。

### 10.10 历史与异常
本地 JSON 原子替换保存任务，最多 50 个，最多 3 个同时运行。完成、失败、取消、中断后可删除；正在运行先取消。
任务失败保留已完成阶段。重新开始创建新任务，不伪装原任务重试成功。不支持多 worker 共享状态。

## 11. 非功能需求
- 响应速度：创建请求即刻返回任务，不等待模型。Mock 研究目标 5 秒级，本机验收为秒级；受进程冷启动和机器影响，不视为线上 SLA。模型 SDK 超时 25 秒，外层 30 秒。
- 数据安全：仅本地 mock；后端读取 .env；模型密钥不传给前端或 MCP 子进程；配置模型时用户输入会发送到模型提供商。仅绑定回环地址，无公网服务承诺。
- 可解释性：保存输入、来源、批准意见、模式、工具日志；检索片段与指令隔离；未知引用触发降级。
- 可扩展性：工具协议、角色与指标逻辑分离；未来可替换知识后端和投放数据适配器。
- 可访问性：键盘焦点、标签页方向键、对话框焦点恢复；移动端单列；prefers-reduced-motion 关闭非必要动画。

## 12. 核心指标
以下为产品评估设计，不宣称本 Demo 已获得真实使用数据。
| 指标 | 计算 / 评估口径 |
|---|---|
| Brief 生成时间 | 提交到完成，分别报告系统耗时和人工等待时间 |
| 用户采纳率 | 业务确认采纳的 Brief / 完成的 Brief，不以复制次数代替 |
| 素材采纳率 | 同口径评审中采纳素材 / 提交素材 |
| CTR / CVR / CPA / ROAS | 按 10.8 公式，接入真实数据前统一事件、币种与归因窗 |
| 报告复用率 | 后续 Campaign 引用过的报告 / 已完成报告 |
| 证据相关性 | 人工评审检索结果是否匹配产品、地区和问题 |
| 降级率 | fallback 阶段数 / 计划模型生成阶段数 |
| 人工修改率 | 带修改意见的确认 / 总确认，用于判断结果适配性而非直接评价好坏 |

## 13. MVP 边界
模拟知识不是市场调研；统计估算不是已运行 A/B 实验；规则检查不是合规认证；多 Agent 是模块化编排，不是完全自治组织；MCP 协议调用真实，但数据源是本地 mock。本版没有身份、权限、多租户、真实投放或公司数据。

## 14. 后续迭代方向
先建立授权与标注评测，再引入向量数据库 / 重排；通过 MCP / Tool Calling 增加可审计的只读工具；完善 A/B 实验模块和指标数据看板；加入多语言本地化人工审校；最后对接投放平台 API。写操作必须具备细粒度权限、预算约束、审批、幂等与回执。

## 15. 广告交付需求（0.3）
| 功能 | 验收条件 |
|---|---|
| 研究交接 | completed Brief 可导入，关键需求匹配，整份 Brief 快照保留；未完成不能关联 |
| 双路径创作 | 素材路径按类型与地区过滤，无匹配可切提示词路径；后者不捏造历史引用 |
| 历史素材 | 6 个合成方案，3 个参考视觉；显示来源、复用方式和合成性质，不使用虚构业绩排名 |
| 创意方案 | 文案、视觉方向、提示词、约束、分镜可编辑；DeepSeek JSON 失败显式降级 |
| 模型选择 | 本地模板 / OpenAI / Google；配置状态与执行成功分开呈现；密钥不进入浏览器 |
| 成本授权 | 内容确认 + 外部发送授权；相同 request_id 复用结果，不自动重试收费调用 |
| 广告交付 | PNG + ZIP；来源、提示词、分镜、审核状态齐全；非图片响应不能标成功 |
| 人工验收 | 未成功不得确认；成功后仍检查文案、图像、产品事实与素材权利 |
| 版本复盘 | 只接受已确认版本，锁定模拟原始数据；指标与样本量通过 measurement MCP 确定性计算 |
| 迭代 | 保留父广告、已确认文案、数据与客户反馈；新方案再次确认后才生成，不覆盖旧版 |

新增状态：方案草稿 → 内容确认 → running → succeeded / failed / interrupted；成功生成后单独记录交付确认与复盘。V 表示创意轮次，job ID 区分同一轮的不同生成。

新增指标定义：需求到首份可审核方案耗时；生成成功率（有效图片 / 提交生成）；客户交付采纳率（确认交付 / 有效生成）；复盘覆盖率（已复盘广告 / 已确认广告）；迭代回流率（创建下一版的复盘 / 完成复盘）。本 Demo 没有真实用户埋点或业务基线，不能宣称指标提升。

非功能：规划并发 3、图像生成并发 2；JSON 原子保存；单进程本机部署；外部生成最长 180 秒，无自动重试；浏览器轮询真实状态。受限图片大小与尺寸，错误响应不暴露服务商原文或密钥。

边界：仅图片可成品交付；视频为分镜与提示词；英语 / 简体中文；不做素材上传、真实广告发布、企业权限、商用版权审核或视频成片。API 与模型接入、数据字段、安全限制见 [广告创意交付说明](AD_CREATIVE_SERVICE.md)。
