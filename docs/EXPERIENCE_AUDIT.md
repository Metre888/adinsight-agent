# 产品体验与升级记录
日期：2026-09-07。范围：原有 React 工作台、接口与本地资料、主操作链路；依据当前项目代码与浏览器体验，不涉及公司资料。

## 旧版实际体验
| 问题 | 体验 / 代码证据 | 处理 |
|---|---|---|
| React 入口白屏 | 启动后空白；未配置 React JSX 插件 | 增加 Vite React 配置，完成生产构建 |
| 信息层级重叠 | 结果、指标、洞察、Brief、复盘、工作流、来源全部长页铺开，段落套卡片 | 单工作台 + 五个结果标签页 |
| 引用不相关 | AI 相机项目检索结果同时含语言学习与 AI 写作案例 | 产品与地区筛选 + 中文字符 TF-IDF |
| 复盘结论固定 | 前端提交百分比字符串；模板固定输出 CVR / ROAS 异常 | 原始计数校验与五指标确定性规则 |
| Agent 过程不真实 | API 一次性返回静态步骤完成状态 | 真实状态机、并行任务、时间与工具调用记录 |
| 没有工具协作 | 原来仅串行函数调用，没有 MCP | 两种 stdio 服务、动态工具发现、角色白名单 |
| 没有决策节点 | 点击生成就直接得到最终 Brief | 研究后等待方向与修改意见确认 |
| 降级不可见 | 模型异常被静默处理 | 阶段 mode、fallback 原因、页面提示与导出记录 |
| 结果难恢复 | 刷新丢失当前结果，无取消与历史 | 本地 JSON、历史、取消、重启状态处理 |
| 入口维护分裂 | React 与手写静态 Demo 各自维护逻辑 | React 构建由 FastAPI 托管，旧 HTML 改为入口说明 |

旧版示例填充、生成和复制本身可以运行；问题不在于没有文字输出，而在于证据匹配、决策记录与可验证性不足。

## 0.2 产品取舍
- MCP 引入在知识与指标两个边界，实际执行工具协议；业务数据仍然是合成的。
- 多 Agent 采用有限角色和共享数据合同，不添加没有任务价值的自由对话角色。
- 并行用于互不依赖的市场 / 竞品 / 复盘；生成在人工确认后执行。
- 保留轻量 RAG，不为了技术名词引入向量数据库；先处理明显的过滤与引用问题。
- 计算与生成分离，实验计划保留统计假设，不宣称显著提升。
- 模型选择可配置，默认 DeepSeek V4 Flash，结构化短任务关闭 thinking；未配置密钥时可以完整展示。

## 验证范围
后端自动测试涵盖真实 MCP 连接与调用、工具白名单、输入计数约束、无分母、中文匹配与空证据、并行阶段、人工审批、重复审批、取消、恢复、Schema / 引用降级、REST 与 SSE。前端通过生产构建。
浏览器验证示例运行、研究结果、人工意见进入 Brief、来源详情、复制实际文本、MCP 连接、场景变化、历史恢复以及桌面 / 移动端布局。
依赖检查：生产前端依赖 npm audit 当前未报告已知漏洞。该检查不是整个系统的安全认证。

## 尚未验证与限制
- 无可用 API Key，未发起真实 DeepSeek 付费请求；只验证兼容调用实现与失败降级。
- 没有真实用户实验、真实竞品数据或广告平台连接，不能声称提升 CTR、收入或团队效率。
- 固定中文类目和地区别名覆盖有限，不是通用多语言检索器。
- 本地 JSON 与无鉴权服务只适合单进程本机演示，不能直接公网运行。
- 当前仓库的规范来源是 0.3 代码与 Markdown 文档。

## 当前技术依据

## 0.3 广告交付验收
- 自动化：16 项后端测试通过；生产前端构建通过；npm audit --omit=dev 未报告已知漏洞。
- 实际浏览器主线：从已完成研究导入 Brief，选择相机素材，编辑客户标题，切换 OpenAI 查看缺少密钥与授权限制，返回本地生成图片，确认交付，填写客户反馈，完成版本复盘，再创建 V2。
- 图像与交付包：测试检查 PNG 解码和 1:1 / 4:5 / 9:16 尺寸，检查交付包五个文件、确认状态与来源；第三方适配使用测试替身检查实际参考图片载荷。
- 桌面 1280×720 / 1440×1024 检查素材、方案与交付页；390×844 检查表单重排和横向溢出。完整移动端交互仍需补充回归，布局检查不等同于全流程验收。
- 修正链路：下一轮保留上一版已确认标题与约束，复盘和客户意见传入规划；浏览器保存提示词草稿、工作区位置与提交请求标识。
- 边界：未配置图片服务密钥，未实际调用 OpenAI / Google 计费生成；无视频成片、无真实投放、无真实收益验证。
